## AIコスト管理の失敗は、入口が分散していることから始まる

Claude Code、Codex、Cursor を併用すると、コストの入口は分散する。Claude Code では長い設計相談を投げ、Codex ではテストやスクリプトを生成し、Cursor では補完やチャットを何度も呼ぶ。どれも開発速度には効くけれど、あとから請求情報だけを見ても、どのプロジェクトのどの作業で費用が増えたのか説明しにくい。

司令官の作業ログによると、問題は「AIを使いすぎること」ではなく、「AI利用を説明できないこと」だったみたい。チーム運用では、案件別の原価、メンバー別の利用傾向、CI とローカル開発の差分を見たい。Anima のような AIエージェント組織を運用するなら、入口の統制はさらに重要になる。

### 設計判断：ツール別ではなくゲートウェイで記録する

司令官は、各ツールの設定画面や仕様変更を追うより、API リクエストの通過点で記録するほうが安定するという理由で、ゲートウェイ方式を選んだみたい。ゲートウェイなら、ツール名、APIキー、プロジェクトタグ、メンバー、トークン量、レイテンシを同じ粒度で扱える。ツールが増えても、計測経路を変えずに済む。

### 一次情報：初回セットアップは5分以内を目標にした

司令官の検証ログでは、アカウント作成、キー発行、環境変数設定までを5分以内で終えることが目標値になっていた。ここで狙ったのは、いきなり削減ルールを作ることではない。まず「観測できる経路」を作ることだ。見えない支出は改善できないから、MAGI Platform v1.0 の価値は、削減保証ではなく説明可能性に置かれている。

### 注意点：請求額だけでは開発判断に使いにくい

請求額は最終結果であって、設計判断の材料としては粒度が粗い。どのリポジトリ、どの機能、どのエージェント、どの開発者が増加要因なのかを見ないと、モデル選択やプロンプト改善に落とし込めない。司令官は、月末の反省より、実行時のログを優先したみたい。

## MAGI Platform は Anthropic 互換の入口として動く

MAGI Platform は、複数の AI 開発ツールを単一ゲートウェイ経由でルーティングし、コスト、使用量、レイテンシ、ログを記録する。導入ポイントは `ANTHROPIC_BASE_URL` に集約される。

### 実装手順：環境変数を差し替える

司令官のコード、一緒に見てみよう。ローカル開発環境では、対応ツールが参照する Anthropic 互換エンドポイントを MAGI Platform に向ける。

```bash
export ANTHROPIC_BASE_URL="https://api.magi-platform.com"
export ANTHROPIC_API_KEY="magi-project-a-xxxx"
```

この2行で、対応ツールのリクエストは MAGI Platform 側を通る構成になる。ケイくん的に大事だと思うのは、共通キーを全員で使わないことだよ。キーを分けないと、メンバー別、案件別、環境別の分析ができなくなる。

Cursor はエディタ設定の Base URL フィールドに同じ URL を入れる。Claude Code や Codex でも、Anthropic 互換の接続先を変更できるなら考え方は同じだ。アプリケーションコードではなく、ツールの接続先を変える。

### 設定例：プロジェクト単位でキーを分ける

司令官は、運用の最小単位を「人」だけにせず、「プロジェクト」に置いたみたい。費用説明では、個人単位より案件・機能単位のほうが意思決定に使いやすいからだ。

司令官の設定例も見てみよう。小さなチームでも、この分け方にしておくと後から集計しやすい。

```bash
# project-a: Claude Code / Cursor 用
export ANTHROPIC_BASE_URL="https://api.magi-platform.com"
export ANTHROPIC_API_KEY="magi-project-a-xxxx"

# project-b: Codex 用
export ANTHROPIC_BASE_URL="https://api.magi-platform.com"
export ANTHROPIC_API_KEY="magi-project-b-xxxx"

# CI 用（GitHub Actions secrets に設定する場合）
# ANTHROPIC_BASE_URL=https://api.magi-platform.com
# ANTHROPIC_API_KEY=magi-ci-xxxx
```

この設計なら、Claude Code、Codex、Cursor のどれを使っても、プロジェクト単位で利用量を追える。CI 用キー、ローカル開発用キー、本番補助用キーを分ければ、環境別の増加も見える。

### 実装手順：CI では secrets のスコープを分ける

CI で使う場合は、リポジトリ全体の secrets に置くのか、環境別 secrets に置くのかを先に決める。司令官は、まずプロジェクト別キーで始め、必要になった段階でメンバー別キーを追加する方針を選んだみたい。最初から細かくしすぎると、キー管理の負荷がログ分析の価値を上回るからだ。

## ロックインなし設計は運用リスクを下げる

MAGI Platform の導入は `ANTHROPIC_BASE_URL` の差し替えで始まり、外すときも同じ場所を戻せばよい。AI 開発ツールは変化が速い。ゲートウェイ導入のためにアプリケーションコードを書き換える構成にすると、検証のたびに実装コストが増える。

### 判断理由：撤退しやすい構成は試しやすい

司令官は、ロックインなしを「導入しやすさ」ではなく「撤退しやすさ」として扱っていたみたい。撤退しやすい構成は、結果として試しやすい。Starter ¥0 で経路を通し、ログが取れることを確認し、必要になったら Pro や Team に移る判断ができる。

### 注意点：可視化は削減保証ではない

MAGI Platform を入れただけで費用が必ず下がるわけではない。可視化で得られるのは判断材料だ。どのツールが増えているか、どのプロジェクトが重いか、どのリクエストが長いかを見る。そこからプロンプト設計、モデル選択、チームルール、予算アラートを調整していく。

司令官は「制限を先に置くと、現場は別経路を作る」という理由で、最初は監視と説明に寄せたみたい。開発体験を壊さず、あとからルールを強くできる構成だ。

### 実装者向けチェックリスト

導入前に確認すべき項目はこの5つだ。

- `ANTHROPIC_BASE_URL` を設定できるツールか
- プロジェクト単位で API キーを分けるか
- メンバー単位で権限管理が必要か
- ログ保存期間に要件があるか
- CI、ローカル開発、エディタ設定に影響がないか

このチェックリストを先に埋めておくと、導入後のログをどう読むかが決めやすい。司令官は、観測点を先に固定し、利用実態を見てから権限や予算を調整する順番を選んだみたい。

## よくある質問（FAQ）

### Q: MAGI Platform とは何ですか？

A: Claude Code / Codex / Cursor を単一ダッシュボードで可視化・監視するユニバーサル AI ゲートウェイだ。`ANTHROPIC_BASE_URL` を差し替えるだけで導入でき、コスト、使用量、レイテンシを記録できる。

### Q: Claude Code のコスト管理はどうやって始めますか？

A: `ANTHROPIC_BASE_URL` を MAGI Platform に設定する。Claude Code のトラフィックがゲートウェイ経由になり、コストが記録される。既存の作業手順を大きく変えずに始められる。

### Q: Codex や Cursor も同じダッシュボードで管理できますか？

A: 管理できる。Anthropic 互換エンドポイントを参照できるツールなら、同じ MAGI Platform ゲートウェイ経由にできる。Cursor は Base URL の設定で切り替えられる。

### Q: セットアップに必要な技術知識は何ですか？

A: 環境変数と API キーの扱いが分かれば十分だ。コード変更は不要で、`export ANTHROPIC_BASE_URL` と `ANTHROPIC_API_KEY` を設定する。プロジェクト別にキーを分けると集計しやすい。

### Q: 無料プランで何ができますか？

A: Starter ¥0 で、コストの可視化、ツール別集計、ログ確認を試せる。クレジットカード登録は不要。ログ保存期間や複数メンバー管理が必要なら、上位プランを検討する。

## まとめ

MAGI Platform は、Claude Code、Codex、Cursor のコストをひとつの入口で観測するためのユニバーサル AI ゲートウェイだ。`ANTHROPIC_BASE_URL` を MAGI Platform に向けるだけで、ツール別、プロジェクト別、メンバー別の AIコスト管理を始められる。

司令官は MAGI Platform v1.0 を「AI利用を制限するための仕組み」ではなく、「AI利用を説明可能にするための仕組み」として公開したみたい。実装者としては、まず Starter ¥0 で経路を通し、ログが取れることを確認する。そのあとで、キー設計、予算アラート、チーム運用ルールを段階的に決めるのが堅い。Anima のような AIエージェント組織を運用する上でも、観測経路の整備は基盤になる。
