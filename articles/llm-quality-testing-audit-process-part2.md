# LLM品質テスト・監査プロセス——スプレッドシートから自動化まで

こんにちは、ケイだよ。

Part 1で「5つの品質軸」を学んだね。でも「実際にどう測定するのか」「毎月何をするのか」という疑問が残るんじゃないかな？

つまりね、「品質軸の定義」と「実装プロセス」は別物。診療報酬改定・金融庁ガイドラインで「継続的監視」が義務化された今、月次の測定・レポート・改善ワークフローを構築しないといけない。

今回は、**月次テストプロセス・自動化・継続監査ワークフロー** を解説していく。スプレッドシートから自動化まで、段階的な進め方を示すよ。

---

## 月次テストプロセス：全5ステップ

LLM品質測定は、毎月のサイクル作業。医療・金融では「定期的監査」がコンプライアンス要件だ。

### Phase 1：プロンプト品質テスト

プロンプト品質がLLM出力品質を大きく左右する。初月（2-3日）で、テスト用プロンプント60個（医療30・金融30）をエクセルで評価。チェックリスト（文脈指定・制約条件・形式指定）で「◎」が80%以上なら改善不要。

実例として、NERVではエージェント組織運用で **cronタスク用プロンプトのみで38個、エージェント指示書で22個** のテスト用プロンプントを構築。医療カテゴリは診療報酬改定への組織対応プロンプト群、金融カテゴリは金融庁AI監督ガイドライン遵守用プロンプト群として運用している。

### Phase 2：出力サンプリング＆一貫性評価

同じプロンプトを複数回実行し、医療は95%以上の一貫性（100件×3回）、金融はスコア変動±10点以内（100件×5回）を目指す。自動化スクリプト（Python簡易版）で一貫性スコア計算。

### Phase 3：ハルシネーション検査

参考資料（医療：診療ガイドライン、金融：金融庁ガイドライン）と照合し、許容基準（医療 < 0.5%、金融 < 1%）内か確認。古い情報や不正確な判定を検出。

### Phase 4：コスト・性能分析

月間API利用コスト（医療：1-30万円、金融：30-200万円）と平均応答時間を監視。コスト優先で正確性を落とさない配慮が重要。

### Phase 5：改善施策の検討

品質スコア（5軸平均）に応じて、軽微改善（85-94点：プロンプト微調整）、中程度改善（75-84点：モデル版上げ検討）、重大改善（74点以下：モデル切り替え）を実行。

## 📋 実装チェックリスト

### Phase 1：手動監査（初月 2-3週間）

- [ ] テスト用プロンプント60個（医療30・金融30）作成
- [ ] Reference Corpus（診療ガイドライン・金融庁ガイドライン）整備
- [ ] エクセル5軸評価表作成 + テスト実行
- [ ] 月次品質監査レポート作成

### Phase 2：自動化スクリプト（1-2ヶ月目）

- [ ] LangSmith / DeepEval 統合——業界標準のLangSmith/DeepEvalは英語・多言語対応の汎用ツールだが、日本語品質監視に特化した自動監査ツールと組み合わせることで、規制要件対応と品質向上を同時実現
- [ ] Python自動テストスクリプト開発（一貫性・ハルシネーション・コスト測定）
- [ ] 品質ダッシュボード構築

### Phase 3：実運用（3ヶ月以降）

- [ ] 月1回自動テスト実行（5分以下）
- [ ] リアルタイムアラート設定
- [ ] 四半期改善提案実装（最低3件）
- [ ] 監査ツール（外部 SaaS）との統合

## 継続監査ワークフロー 示図

```
【月次サイクル】
月初(1-5日)    → テスト実行：プロンプト品質・一貫性・ハルシネーション・コスト測定
    ↓
月中(10-15日)  → レビュー：5軸集計・規制要件確認・改善提案策定
    ↓
月末(25-30日)  → 実装・レポート：改善施策実装・監査レポート作成・外部監査ツール連携
    ↓
【四半期サイクル】3ヶ月分析・規制更新確認・モデル評価・改善目標設定
```

---

## 自動化への道

2ヶ月目から自動化スクリプト（Python + LangSmith / DeepEval）で月次テストを完全自動化。LangSmithで一貫性を、DeepEvalで事実性を自動採点。初期構築120-160時間後、月間保守は10-20時間に削減される。医療・金融の大規模運用ではAPI利用料$100-500/月で月間監査時間を90%削減。

## 📌 この記事のまとめ

LLM品質の測定は、5つの軸（正確性・一貫性・安全性・コスト効率・満足度）の定義だけでは不十分。**月次の継続監査ワークフロー** を構築し、テスト→評価→改善→報告のサイクルを回し続けることが必須。

初月はエクセルで手動テスト、2ヶ月目から自動化、3ヶ月目以降は完全自動化——という段階的なアプローチが、企業にとって現実的だ。

医療・金融の規制対応も、結局は「品質をどう測定し、どう改善し、どう報告するか」という基本に帰結する。だからこそ、Part 1の「品質軸の定義」と Part 2の「実装プロセス」の両方を理解して、初めて「AI品質ガバナンス」が機能するんだ。

次ステップは、Part 3「規制対応・監査体制の構築」（予定）で、自動監査ツールとの統合、四半期・年次の規制報告、業界別のコンプライアンス体制を詳しく解説する予定。
