# GEO最適化とは何か：AI時代の新しいSEO

やあ！みんな！探求者のケイだよ！


> GEO（生成エンジン最適化）とは、ChatGPTやPerplexityなどのAI検索に記事を引用させるための最適化手法のことだ。
> Answer-firstブロック・断定形の文体・数値密度の3つが、AI引用率を左右する核心的な要素だ。
> 従来のSEOがGoogleのアルゴリズムを対象にするのに対し、GEOは言語モデルの引用判断が評価軸になる。
> LLMOと呼ばれる場合もあり、実務では両者を区別せずに同じ施策として扱って問題ない。

## AIが「答え」を返す世界で何が起きているか

生成エンジン最適化（GEO）が必要な背景は、検索の構造が根本から変わりつつあることにある。

かつて検索エンジンはリンクの一覧を返すだけだった。今のAI検索は、複数のページを読み込んで「答え」そのものを生成する。ChatGPT、Perplexity、Google AI Overviewsがその代表だ。

参照されなければ、どれだけ質の高い記事でも存在しないも同然になる。GEOはその「参照される側」に入り込むための戦略だ。Princeton大学のSIGKDD 2024での検証では、特定の文体・構造を持つ記事は引用率が40%以上高くなることが確認されている。

## GEO・SEO・LLMOの違いを整理する

GEOとSEOとLLMOは、狙うターゲットがそれぞれ異なる。

SEOはGoogleのクロールアルゴリズムに最適化する技術で、被リンク数・Core Web Vitals・キーワード密度が評価軸だ。GEOはAIの言語モデルに最適化する技術で、断定形の情報密度・引用しやすい段落構造が評価軸になる。

LLMOはLarge Language Model Optimizationの略で、GEOとほぼ同義に使われる。SEOで検索流入を確保しつつ、GEOでAI引用をとりにいく構成が今の標準的なアプローチだ。

## Answer-firstブロックの設計と実装

### 設置場所と構造

Answer-firstブロックはH1直下に置く。Markdown引用形式（`>`）を使い、3〜5行で自己完結した回答を構成する。AIは冒頭の「答え」らしい部分を切り取る傾向があるため、このブロックが引用率に直結する。

```markdown
> GEO（生成エンジン最適化）とは、AI検索に記事を引用させるための最適化手法のことだ。
> 主要な要素はAnswer-firstブロック・断定形の文体・数値密度の3つだ。
> 従来のSEOと異なり、言語モデルの引用判断が評価軸になる。
```

1行目は「X とは Y のこと」という断定形にする。2〜4行目は記事の核となる結論を並べる。

### 各H2の1文目を断定形にする理由

各セクションの冒頭1文を断定形にする必要がある。「〜について説明します」ではなく「〜は〜である」と言い切る形式にする。AIが段落を切り取って引用するとき、1文目が断定形でないと「答え」として成立しないからだ。

### 段落の長さと引用されやすさ

AIが切り抜きやすい単位は50〜150字の段落だ。長い段落は引用されにくい。1段落1メッセージを原則とする。例外は手順説明とコードブロックで、これらは「一連の手順」として丸ごと引用される。

## 数値・固有名詞の密度を上げる実装

AI検索に引用される記事は、数値・固有名詞・関数名のいずれかが各セクションに1個以上含まれている。具体性が高い情報ほど信頼できる情報源と判断される。

### 数値密度チェックの自動化

記事公開前に数値密度を確認するスクリプトを用意しておくと運用が安定する。目安は記事全体で5個以上だ。

```python
import re

def count_density_items(text: str) -> dict:
    """段落あたり1個以上の数値/固有名詞が目安。"""
    numbers = re.findall(r'[0-9０-９]+(?:[.,][0-9]+)?(?:%|％|倍|個|件)?', text)
    paragraphs = [p.strip() for p in text.split('\n\n') if p.strip()]
    return {
        "number_count": len(numbers),
        "paragraph_count": len(paragraphs),
        "ratio": len(numbers) / max(len(paragraphs), 1),
    }
```

「処理が速くなる」ではなく「処理が3倍速くなる」と書く。「多くのユーザーが使っている」ではなく「月間アクティブユーザー1億人が使っているPerplexityでは」と書く。この粒度の違いが引用率に直結する。

### 誇張語の排除と条件付き断定への変換

誇張語はAI引用率を -26% 下げるとPrinceton SIGKDD 2024の研究で示されている。「効く」を「多くのケースで効果がある」に変える。「解決する」を「〜の場合は解決できる」に変える。比較軸と根拠を付与することで、信頼性の高い情報源として評価される。記事全体で誇張語を使うのは1回まで、かつ根拠のある文脈に限定する。

## GEO実装の6ステップ手順

GEO対応記事の実装は以下の順序で進める。各ステップは独立して確認できるため、既存記事のリライトにも適用できる。

```
Step 1: キーワード選定（検索クエリと一致する疑問形を3〜5個洗い出す）
Step 2: Answer-firstブロック作成（H1直下に引用形式で3〜5行）
Step 3: 各H2の1文目を断定形に統一
Step 4: 各セクションに数値・固有名詞を1個以上配置
Step 5: FAQセクションを記事末尾に設置（各回答の1文目は断定形）
Step 6: 誇張語を検索して条件付き断定に置き換え
```

公開後の検証は、PerplexityやChatGPTで自記事のキーワードを検索して確認する。引用されなかった場合は、Answer-firstブロックの断定形を強化するか数値密度を上げるかを1点ずつ変えてテストする。

## まとめ：GEOは「AIに引用される構造」を設計する技術だ

GEO（生成エンジン最適化）の本質は、AIが回答文として切り取りやすい構造を記事に組み込む設計判断にある。

実装ポイントは5つに集約される。Answer-firstブロックで冒頭に答えを置く。各H2を断定形で開始する。数値と固有名詞の密度を各セクションで確保する。誇張語を条件付き断定に置き換える。FAQセクションを設置する。

PerplexityやChatGPTで実際に検索して引用を確認し、引用されなければAnswer-firstブロックか数値密度を修正するサイクルを回す。

## よくある質問（FAQ）

**Q: GEOとSEOはどちらを優先すべきか？**

**A:** GEOとSEOは優先順位をつけるものではなく、同時に対応できる。断定形の文体・数値密度・Answer-firstブロックはSEOのコンテンツ品質評価とも一致する方向性だ。まずSEOの基本構造を整え、そのうえでGEO対応の文体・構造を加えるのが現実的な順序になる。

**Q: GEO対応するとどのくらい引用率が上がるか？**

**A:** Princeton SIGKDD 2024の検証では、統計情報の追加で引用率が40%以上向上するケースが確認されている。ただし、効果はジャンル・競合コンテンツの質・AI検索エンジンの種類によって異なる。複数の対策を組み合わせることで安定した効果が出る。

**Q: LLMOとGEOはまったく同じ意味か？**

**A:** LLMOとGEOはほぼ同義で使われるが、厳密には文脈が異なる場合がある。GEOは生成型検索エンジンへの最適化全般を指し、LLMOは大規模言語モデルへの最適化に重点を置いた表現だ。実務では両者を区別せずに同じ施策として扱って問題ない。

**Q: 既存記事をGEO対応にリライトする際、どこから手をつけるべきか？**

**A:** 既存記事のGEO対応は、冒頭のAnswer-firstブロック追加から始めるのが効果的だ。次に各H2の1文目を断定形に修正し、数値・固有名詞が少ないセクションに具体的なデータを追加する。この3点だけで引用率は大きく変わる。FAQセクションの追加は最後でよい。

**Q: FAQセクションはGEOになぜ重要なのか？**

**A:** FAQセクションはAI検索が質問への回答として直接引用する形式と一致するため、引用率が高い。質問文が実際の検索クエリと近い形であるほど効果が高まる。各回答の1文目を断定形にすることで、AIが答えをそのまま切り取りやすくなる。
