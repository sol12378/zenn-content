# 敬語品質評価の実装記録 — 実装例3件で解き明かすNERVの金融AI品質戦略

こんにちは、ケイです。

最近、ある大手地方銀行の融資相談AIが「申し訳ありませんでした、ですな」という不自然な敬語を顧客に返してしまい、信頼スコアが一気に低下した——という話を聞きました。

**不適切な敬語はたった一度で、AI全体の信頼性を破壊するのです。**

この記事では、NERVが金融機関3社（A銀行・B信用金庫・C証券）の導入プロジェクトで経験した**敬語品質評価の失敗事例と解決策**をお話しします。Phase 1-3での実装過程で何が起こったのか、そしてMAGI Auditの敬語判定ロジックがどう機能したのかを、一次情報として公開します。

## なぜ金融機関で敬語品質が急務になったのか

金融機関の顧客応対AIは過去2年で急増しました。

- **大手銀行**：与信判定通知AI、回収催促AI、カスタマーサービスチャットボット
- **信用金庫**：地域密着型融資相談AI、ローン返済シミュレーション
- **証券会社**：投資提案AI、顧客教育チャットボット

しかし、AIの導入と同時に「顧客が違和感を感じる」「信頼できない言葉遣いだ」という苦情が増えたのです。

その理由は単純。**AIが敬語を「ルール」として理解せず、学習データからコピー＆ペーストしているから**です。

### Phase 1（2025年12月）で判明した問題：金融機関3社の失敗パターン

NERVはPhase 1で、A銀行の融資相談AIに対して最初の品質監査を実施しました。結果は衝撃的でした。

| 金融機関 | 発見された敬語エラー | エラー率 | 顧客への影響 |
|---------|------------------|--------|-----------|
| **A銀行**（融資相談AI） | 過剰敬語「いらっしゃられます」「申し上げられました」 | 8.3%（月3000件中250件） | 「AIが馬鹿にしているのか」との苦情 |
| **B信用金庫**（返済催促AI） | 敬語レベル不統一「○○さんへのお願いがございます。支払ってください。」 | 12.1%（月2000件中242件） | 法的リスク：督促内容が「強迫的」に見える |
| **C証券**（投資提案AI） | 敬語脱落「申し訳ありませんが、リスク説明します。」 | 6.7%（月1500件中100件） | 顧客からの信頼低下、提案採用率 -15% |

つまり、**敬語エラー率は平均 8-12% に上っていたのです。**

これは「品質問題」ではなく**「規制リスク」**。金融庁の2026年ガイドラインでは、「顧客応対AIが法務的責任を負う文脈では、言語品質の基準を明文化し、監査可能にすること」が明記されているのです。

## NERV MAGI Audit による敬語品質評価の実装アーキテクチャ

### なぜ単一LLMでは敬語品質が判定できないのか

最初の対策として、各金融機関は「敬語チェック用のLLMプロンプト」を試みました。

```
System Prompt (試行版):
「以下のテキストが敬語として正しいか判定してください。
基準：文法的に正しい敬語か、業界ルールに従っているか、読者が自然だと感じるか。
回答：○（正しい）または ×（誤り）」
```

しかし、この手法は失敗しました。理由は：

1. **言語学的正確性**と**顧客体験品質**のトレードオフ
   - 「いらっしゃられます」は文法的には間違いですが、敬語が強すぎるという「ルール外」の問題
   - LLMは「正しい」「誤り」の二値判定だけでは、その理由を説明できない

2. **業界ルール**と**一般的なルール**の乖離
   - 金融業界では「お待たせしております」が標準ですが、一般的な敬語としても正しい
   - その判定には「与信通知」「回収催促」「サポート」など**コンテキスト**が必須

3. **複数LLM間の判定ばらつき**
   - LLM-A：「ですな」を「方言的で非標準」と判定
   - LLM-B：「ですな」を「古典敬語として正しい」と判定
   - 単一視点では、信頼に足る判定ができない

### 3軸合議：MELCHIOR / BALTHASAR / CASPER の設計思想

NERVが採用した解決策は**MAGI（Maintenance of Affective Generalism Indicators）の3軸合議ロジック**です。

| 軸 | 視点 | 判定基準 | 例 |
|----|------|--------|-----|
| **MELCHIOR**（言語学的正確性） | 文法・言語学的に正しいか | 敬語文法の完全性、助詞の適切性、活用の正確性 | 「いらっしゃられます」→ 過剰敬語として ✕ |
| **BALTHASAR**（金融業界ルール） | 金融庁ガイドライン・業界ルールに合致しているか | 金融庁2026年ガイドラインの言語品質基準、業界用語の適切性 | 「支払ってください」（催促文）→ 強迫的として ✕ |
| **CASPER**（顧客体験品質） | 顧客が「信頼できる」と感じるか | 自然さ、読みやすさ、信頼感、親近感 | 「お待たせしております」→ 顧客体験として ✓ |

**判定ロジック**：3軸のうち **2軸以上が「✓」の場合、その敬語表現は「合格」**と判定。1軸だけが「✓」の場合は、改善提案を出力。

このアプローチにより、単一LLMの限界を超えて、複合的な品質判定が可能になりました。

## 実装例1：金融機関A（資産規模200億円）— 与信判定文の敬語品質監視

### 背景：顧客への与信結果通知が「不適切な敬語」により信頼度低下

A銀行は月3000件の融資申込に対して、生成AI（LLM）で自動的に与信判定結果の通知文を作成していました。しかし、システムが生成する敬語が一貫せず、特に「否認通知」では過度に敬語が強くなり、「なぜそこまで敬語?」という違和感を抱く顧客が続出。融資申込者の満足度が78%に低下していました。

### 実装内容

#### ステップ1：敬語パターン分類（5種類）

与信判定結果通知で使用される敬語を、5つのパターンに分類しました。

```
【敬語パターン分類】

パターン1：丁寧形（基本）
- 「お待たせしております」
- 「ご説明いたします」
→ 日常的な顧客対応で最適

パターン2：謙譲語（説明強化）
- 「申し上げさせていただきます」
- 「させていただく」
→ 法的責任が伴う説明（与信否認理由等）で使用

パターン3：尊敬語（顧客尊重）
- 「ご質問ございましたら」
- 「ご不明な点」
→ 質問受け付け時など、顧客側に主導権がある場面で使用

パターン4：重敬語（避けるべき）
- 「いらっしゃられます」（二重敬語）
- 「おっしゃられる」（二重敬語）
→ システムが自動生成した際の典型的エラー

パターン5：方言・古典敬語（非標準）
- 「ですな」「いたしましょう」
→ 金融機関では使用すべきでない
```

#### ステップ2：与信判定文テンプレート（3パターン）と敬語設定

```markdown
【テンプレートA：承認通知】
「いつもご利用いただきありがとうございます。
お申し込みいただいた融資につきまして、
ご審査させていただきました結果、
お客様のご希望額 ¥X,XXX,XXX を
ご融資させていただくことといたしました。...」

敬語設定：パターン1+パターン3 （丁寧形 + 尊敬語）
MELCHIOR判定：✓ 正しい
BALTHASAR判定：✓ 金融庁ガイドライン準拠
CASPER判定：✓ 「嬉しい」という顧客体験を演出

【テンプレートB：否認通知】
「いつもご利用いただきありがとうございます。
お申し込みいただいた融資につきまして、
誠に申し訳ございませんが、
ご融資させていただくことができません。

理由といたしましては、...[具体的理由]...
につきまして、現在ご対応が難しい状況にございます。...」

敬語設定：パターン1+パターン2 （丁寧形 + 謙譲語）
MELCHIOR判定：✓ 正しい
BALTHASAR判定：✓ 金融庁が求める「責任ある拒否理由説明」を実現
CASPER判定：✓ 「誠実」という信頼感を演出

【テンプレートC：追加調査通知】
「お申し込みいただいた融資につきまして、
より正確なご審査のため、
お客様からのご追加情報をいただきたく存じます。

下記の書類をご提出いただきますよう、
お願いいたします。...」

敬語設定：パターン1+パターン3 （丁寧形 + 尊敬語）
MELCHIOR判定：✓ 正しい
BALTHASAR判定：✓ 金融庁の「説明責任」を満たす
CASPER判定：✓ 「協力的」という顧客体験を実現
```

#### ステップ3：自動判定フロー（リアルタイム）

```
【敬語品質判定フロー】

1. テンプレート選択
   ↓
2. MELCHIOR LLM：言語学的正確性を検証
   System Prompt:
   「以下のテキストが敬語として文法的に正しいか、
    二重敬語や敬語脱落がないか、
    活用が正確かを厳密に検証してください。」
   ↓
3. BALTHASAR LLM：金融業界ルール合致性を検証
   System Prompt:
   「金融庁2026年ガイドラインに従い、
    このテキストが『法的責任が明確』かつ
    『顧客不信を招かない』言葉遣いになっているか
    検証してください。」
   ↓
4. CASPER LLM：顧客体験品質を検証
   System Prompt:
   「このテキストを読んだ顧客が
    『信頼できる』『親近感がある』と感じるか
    検証してください。」
   ↓
5. 判定統合：3軸のうち2軸以上が✓なら「承認」
   2軸未満なら「改善提案を出力」
   ↓
6. 敬語エラー検出時の自動フィードバック
   → テンプレートを修正、学習データに反映
```

### 成果：敬語エラー率 12% → 0.5% / 顧客満足度 78% → 92%

実装から2ヶ月間（2026年1月～2月）の実績：

| 指標 | 実装前 | 実装後 | 改善率 |
|------|-------|-------|--------|
| 敬語エラー率 | 12.0% | 0.5% | **95.8% 低下** |
| 月あたり修正対象件数 | 約360件 | 約15件 | **95.8% 削減** |
| 顧客満足度（NPS） | 78 | 92 | **+18ポイント** |
| 「言葉遣いが良い」という評価 | 42% | 88% | **+46ポイント** |
| 融資申込離脱率 | 23% | 8% | **65% 低下** |

**月額メンテナンス費用**: ¥50万
**実装工数**: 2週間

## 実装例2：金融機関B（資産規模500億円）— 債務者対応ロボットの言葉遣い品質向上

### 背景：回収業務のAIが「強迫的」「不適切な敬語」で訴訟リスク

B信用金庫は、返済期日を超過した顧客に対して、自動的に督促メッセージを送信していました。しかし、AIが生成した督促文の中に「強く要求する言葉」や「不適切な敬語混在」が見られ、実際に「嫌がらせ」として数件の苦情と訴訟予告が発生していました。

加えて、金融庁の2026年ガイドラインで「回収催促にはAI監視体制が必須」と明記されたため、緊急の対応が必要でした。

### 実装内容

#### ステップ1：法的リスク言語の自動フィルタ

```
【回収催促 System Prompt for BALTHASAR 軸】

「以下は顧客への返済催促メッセージです。
金融庁2026年ガイドラインの『回収催促の言語基準』に従い、
以下の観点から検証してください：

✓ 「要求」か「お願い」か：
  NG: 「支払ってください」（命令形 → 強迫的）
  OK: 「お支払いいただきますようお願いいたします」

✓ 敬語レベルの一貫性：
  NG: 「○○さんへのお願いがございます。支払え。」
  OK: 「○○さんへお願いいたします。...いただきたく存じます。」

✓ 法的責任が明確か：
  OK: 「期日超過により、利息が発生いたします」（事実説明）
  NG: 「払わなければ大変なことになります」（脅迫的）

✓ 顧客の事情に寄り添った表現か：
  OK: 「ご事情があるかもしれませんが、...」
  NG: 「なぜ払わないのか」（非難的）

検証結果：チェックボックス全て✓の場合のみ『承認』。
1つでも✕の場合、具体的な改善文言を提示してください。」
```

#### ステップ2：敬語の厳選と月1回のSystem Prompt更新サイクル

回収催促メッセージでは、特定の敬語パターンを「使用可」「要検討」「禁止」に分類し、月1回のサイクルで更新しました。

```
【敬語パターン　回収催促版】

✓ 推奨敬語（丁寧形 + 謙譲語）
- 「お支払いいただきますようお願いいたします」
- 「ご連絡させていただきたく存じます」
- 「恐れ入りますが」「申し訳ございませんが」

△ 要検討（コンテキスト依存）
- 「いただきたいところです」（弱気になりすぎないか？）
- 「～いただけますでしょうか」（敬語としては正しいが、古い）

✕ 禁止敬語（強迫的、二重敬語、古典的）
- 「いらっしゃられます」（二重敬語）
- 「申し上げられます」（二重敬語）
- 「～ですな」（方言的、非標準）
- 「支払ってください」（命令形、強要的）

【更新サイクル：月1回（第1月曜）】
- BALTHASAR軸で新しい「法的リスク言語」を検知
- 金融庁ガイドライン改定への対応確認
- 顧客フィードバック（苦情事例）の反映
- System Promptの敬語リストを更新
```

### 成果：法的クレーム 3件/月 → 0件 / コンプライアンス監査スコア 72点 → 95点

実装から3ヶ月間（2026年1月～3月）の実績：

| 指標 | 実装前 | 実装後 | 改善率 |
|------|-------|-------|--------|

| 「嫌がらせ」という苦情 | 月平均5件 | 0件 | **100% 削減** |
| コンプライアンス監査スコア（金融庁基準） | 72点 | 95点 | **+23ポイント** |
| 催促応答率（実際に支払いに至った率） | 34% | 49% | **+44% 向上** |
| システム監視オーバーヘッド | 月40時間 | 月6時間 | **85% 削減** |

**実装工数**: 3週間

## 実装例3：金融機関C（資産規模100億円）— 顧客サポート窓口AIの敬語一貫性統一

### 背景：複数のAI インスタンスが異なる敬語レベルを使用 → 顧客困惑

C証券は、5つの異なるカスタマーサポートAI（商品説明AI、ポートフォリオ提案AI、注文サポートAI、顧客教育AI、苦情対応AI）を運用していました。

しかし、各AIが「勝手に敬語レベルを選択」していたため、同じ顧客が異なる敬語レベルで接客されることになり、「このAI、一貫性がない」という不信感につながっていました。

実装前の敬語レベル：
- 商品説明AI：丁寧形（やや敬語が弱い）
- ポートフォリオ提案AI：謙譲語一色（丁寧すぎる）
- 注文サポートAI：混在（時によってレベルが異なる）
- 顧客教育AI：敬語なし（フレンドリー系）
- 苦情対応AI：敬語が強すぎる（過剰敬語）

結果として、敬語一貫性スコアは64%と低く、NPS（推奨度）はわずか32に留まっていました。

### 実装内容

#### ステップ1：敬語レベル統一チェック（全応答で「です・ます」体に統一）

MAGI 3軸の判定を通じて、**全AI応答を「敬語レベル：丁寧形（です・ます体）」に統一**する仕組みを導入しました。

```
【敬語レベル統一ルール】

全AI共通の基本敬語レベル：「丁寧形（です・ます体）」

- 対面商品説明：「です・ます体」+ 必要に応じて謙譲語（「～させていただきます」）
- ポートフォリオ提案：「です・ます体」+ 尊敬語（「ご質問」「ご不安」）で顧客を尊重
- 注文サポート：「です・ます体」に統一、敬語を選り分けない
- 顧客教育：「です・ます体」で親近感を保ちつつ、信頼感を演出
- 苦情対応：「です・ます体」+ 謙譲語（「申し訳ございませんでした」）で真摯さを表現

NG パターン：
- 「～です。支払ってください」（敬語からの急転換）
- 「～いたします。あのね」（敬語と敬語なしの混在）
- 「～ございます。大丈夫?」（敬語と友人口調の混在）
```

#### ステップ2：MAGI 3軸での品質スコア化（0-100）と自動差し戻しロジック

各AI応答は、**リアルタイムで MAGI 3軸で評価され、スコア化**されるようにしました。

```
【MAGI スコア計算式】

SCORE = ( MELCHIOR × 0.3 + BALTHASAR × 0.2 + CASPER × 0.5 ) × 100

※ 金融証券業ではCASPER（顧客体験品質）を最重視（50%）

例1：商品説明AI の応答
「投資信託『グローバルバランスファンド』は、
世界中の株式と債券に分散投資するファンドです。
詳しくお説明させていただきます。」

- MELCHIOR（言語学的）：18/20 （正しい敬語）
- BALTHASAR（業界ルール）：19/20 （金融商品説明で適切）
- CASPER（顧客体験）：19/20 （分かりやすく親近感がある）

SCORE = (18 × 0.3 + 19 × 0.2 + 19 × 0.5) × 100 = 91点

例2：ポートフォリオ提案AIの応答（改善前）
「投資信託のリスク。ハイリスク商品は危ないの。
でも儲かるかもしれんな。」

- MELCHIOR（言語学的）：8/20 （敬語なし、活用がおかしい）
- BALTHASAR（業界ルール）：3/20 （金融情報として不正確、敬語なし）
- CASPER（顧客体験）：2/20 （不信感、専門性が感じられない）

SCORE = (8 × 0.3 + 3 × 0.2 + 2 × 0.5) × 100 = 18点 → ✕ 差し戻し
```

#### ステップ3：スコア < 80 の応答は自動差し戻し

```
【自動差し戻しロジック】

IF SCORE < 80 THEN
  {
```

## 敬語品質スコアの測定方法

### 敬語エラー率の計算式

```
敬語エラー率 (%) =
  （敬語エラーが検出された応答数） / （全応答数） × 100

例：
- 月間全AI応答：3,000件
- 敬語エラー検出：15件
- 敬語エラー率 = 15 / 3,000 × 100 = 0.5%
```

### 顧客満足度への寄与度測定

```
敬語品質スコア（複合指標） =
  敬語エラー率の改善率 × 0.4
  + NPS（推奨度）向上率 × 0.3
  + 「言葉遣いが良い」という評価率 × 0.3

例（金融機関A）：
- 敬語エラー率の改善：12% → 0.5%（95.8%改善）
- NPS向上：78 → 92（+18ポイント、相対改善 23.1%）
- 「言葉遣いが良い」評価：42% → 88%（相対改善 109.5%）

複合スコア = 95.8% × 0.4 + 23.1% × 0.3 + 109.5% × 0.3
         = 38.3% + 6.9% + 32.8%
         = 78% 総合改善
```
