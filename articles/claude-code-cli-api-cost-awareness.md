# Claude Code CLIのAPIコスト、把握できていますか？

## はじめに

Claude Codeを使い始めて、最初の数週間は純粋に感動した。

「こんなにコードを書いてくれるのか」「レビューまでやってくれるのか」と、AIの進化を実感しながら開発を続けていた。

ところが、1ヶ月後に来たAnthropicの請求を見て少し驚いた。想定より30%ほど多かった。

その瞬間、自分がどのリクエストにいくら使っているか、まったく把握していないことに気づいた。

この記事は、そこから考えたこと——**Claude Code CLIのAPIコストをどう管理するか**——についてまとめたものです。

---

## Claude Codeを使うと、実際いくらかかるのか

まず現実的な数字を見てみよう。

Claude Codeは内部的にClaude APIを呼び出している。主に使われるのは以下のモデルだ。

| モデル | 入力トークン | 出力トークン |
|--------|------------|------------|
| Claude 3.5 Sonnet | $3 / 1M tokens | $15 / 1M tokens |
| Claude 3 Opus | $15 / 1M tokens | $75 / 1M tokens |
| Claude 3 Haiku | $0.25 / 1M tokens | $1.25 / 1M tokens |

（2026年4月時点の目安価格。最新情報はAnthropicの公式サイトで確認してください）

Claude Codeは1回のインタラクションで、数千〜数万トークンを消費することがある。

具体的なシナリオで試算してみよう。

### シナリオ1：1日2時間のライトユーザー

- 1回のやり取り: 平均5,000トークン（入力3,000 + 出力2,000）
- 1日のインタラクション数: 約30回
- 1日の消費トークン: 150,000トークン
- Claude 3.5 Sonnet使用時の1日コスト: 約$1.35（約200円）
- **月額換算: 約$40（約6,000円）**

### シナリオ2：1日6時間のヘビーユーザー

- 1回のやり取り: 平均10,000トークン（コードレビューや大きなリファクタを含む）
- 1日のインタラクション数: 約100回
- 1日の消費トークン: 1,000,000トークン
- Claude 3.5 Sonnet使用時の1日コスト: 約$9（約1,350円）
- **月額換算: 約$270（約40,000円）**

使い方によって、月数千円から数万円まで大きく変わる。

**あなたは、シナリオ1のライトユーザー？それとも、シナリオ2のヘビーユーザー？ここからは、自分の使い方に照らし合わせながら読んでみてください。**

## なぜコスト管理が難しいのか

Anthropicのコンソールには請求情報が表示される。だが、個人開発者が「もっと知りたい」と感じる情報が不足している。

### コンソールで見られること

- 月次・日次の総コスト
- APIキーごとの使用量（複数キーを持つ場合）

### コンソールで見えないこと

- **どのリクエストがコストを押し上げているか**
- **どのプロンプトが無駄に長いか**
- **モデルの切り替えがコストにどう影響しているか**
- **品質の低い回答が多発している時間帯はいつか**

特に複数のプロジェクトでClaude Codeを使っている場合、「どのプロジェクトに何円使ったか」が標準機能だけでは追えない。

**ここで質問：あなたはClaude Codeを1人で使っている？それとも、チームの開発環境の一部として使っている？**

---

## チュートリアル：Claude Code コスト管理の基本3つの方法

現在、個人開発者が取れる管理手段をまとめてみた。

### 方法1：Anthropicコンソールでの目視確認

**メリット**: ゼロコスト、設定不要
**デメリット**: 過去データしか見えない、ブレイクダウンが粗い

月次の振り返りには使えるが、リアルタイムの制御には向かない。

### 方法2：API利用上限の設定

AnthropicはAPIキーに月次の利用上限を設定できる。

**メリット**: 予算超過を防げる
**デメリット**: 上限に達すると開発が止まる、しきい値の最適値がわからない

「上限を超えたら止まる」という手段は、緊急ブレーキとしては機能するが、日々の最適化には使えない。

### 方法3：自前でプロキシを立てる

APIリクエストをすべて中継するプロキシサーバーを自作し、ログを取る方法。

**メリット**: 詳細なログが取れる、カスタマイズ可能
**デメリット**: 実装コストが高い、運用負担がある

実際にこれをやっている開発者は多いが、「毎回自作するのは非効率だ」という声も聞く。

---

## 本当に必要なのは「見える化」だ

コスト問題の本質は、**見えないことによる不安と最適化の遅れ**だと思う。

見えていれば:
- 「このプロジェクト、今月あと$20使える」とわかる
- 「ここのプロンプトが無駄に長い」とわかる
- 「OpusじゃなくてもこのタスクはHaikuで十分だ」とわかる

見えなければ:
- 請求が来るまで気づかない
- 最適化のしようがない
- 不安で使い方を萎縮させてしまう

コスト管理の目的は、使い方を減らすことではなく、**適切な量を適切な場所に使うこと**だ。
